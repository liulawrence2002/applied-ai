# LendingClub Interest Rate Prediction

Predict `int_rate` for LendingClub loan applications using application-time features only. The active project data is the assignment-provided dataset in `true data/`; the older `data/` slice and archived scripts are retained only for historical comparison.

## Canonical Data Source

**Use `true data/` for all current EDA, feature engineering, modeling, validation, reporting, and test predictions.**

- Train: `true data/LC_train.csv`
  - 100,000 rows x 39 columns
  - Contains target column `int_rate`
  - Contains post-origination leakage column `loan_status`, which must be dropped before modeling or non-leakage EDA
- Test: `true data/LC_test.csv`
  - 10,000 rows x 39 columns
  - Contains `ID`
  - Does not contain `int_rate`
  - Contains `loan_status`, which must also be dropped

Do not use `data/LC_train.csv`, `data/LC_test.csv`, or `data/archive/loan.csv` for current analysis unless explicitly auditing the previous attempt. Any newly created notebook, script, report, or model must resolve its input files from `true data/`.

## Current EDA Status

The current EDA lives in:

- `notebooks/01_eda.ipynb`
- `EDA_REPORT.md`
- `outputs/eda/`

These EDA artifacts are based on `true data/LC_train.csv` and `true data/LC_test.csv`.

Important findings from the true-data EDA:

- FICO columns are present: `fico_range_low`, `fico_range_high`.
- `loan_status` is present but is post-origination leakage and must be dropped immediately after load.
- `grade`, `sub_grade`, and `installment` are absent from this dataset.
- There are no date columns such as `issue_d` or `earliest_cr_line`, so temporal validation is not possible on this slice.
- Modeling should use a random train/validation split unless new valid temporal information is added.
- Several numeric fields arrive as string-encoded values with literal `NA`; load with explicit null handling and numeric schema overrides.

## Data-Loading Requirements

When loading the current data:

```python
from pathlib import Path
import polars as pl

PROJECT_ROOT = Path.cwd().resolve()
if PROJECT_ROOT.name == "notebooks":
    PROJECT_ROOT = PROJECT_ROOT.parent

DATA_DIR = PROJECT_ROOT / "true data"

STRING_NUMERIC_COLS = [
    "dti", "revol_util", "all_util",
    "mo_sin_old_il_acct",
    "mths_since_last_record", "mths_since_rcnt_il",
    "mths_since_recent_bc", "mths_since_recent_inq",
]

NUMERIC_OVERRIDES = {c: pl.Float64 for c in STRING_NUMERIC_COLS + ["tot_cur_bal"]}

train = pl.read_csv(
    DATA_DIR / "LC_train.csv",
    schema_overrides=NUMERIC_OVERRIDES,
    null_values=["NA"],
    infer_schema_length=20000,
)

test = pl.read_csv(
    DATA_DIR / "LC_test.csv",
    schema_overrides=NUMERIC_OVERRIDES,
    null_values=["NA"],
    infer_schema_length=20000,
)
```

Then drop leakage:

```python
LEAKAGE_COLS = ["loan_status"]
train = train.drop(LEAKAGE_COLS)
test = test.drop(LEAKAGE_COLS)
```

## Modeling Guidance For True Data

- Use `fico = (fico_range_low + fico_range_high) / 2` and drop the raw pair if collinearity matters.
- Drop `loan_status` unconditionally before fitting.
- Drop or explicitly encode high-cardinality free text such as `emp_title`; drop `title` if it remains a one-to-one duplicate of `purpose`.
- Parse `term` to numeric months or treat it as a categorical.
- Map `emp_length` ordinally.
- Add missingness flags for semantically meaningful `mths_since_*` nulls.
- Fit imputers, encoders, and scaling logic on training folds only; apply learned values to validation and test.
- Use random validation because the true-data slice has no date columns.
